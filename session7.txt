Reusable Module — A Directory With a Contract

A Terraform module is just a directory containing main.tf, variables.tf, and outputs.tf. The module boundary is a contract:
every value enters through a variable, every useful value leaves through an output, and nothing is hardcoded inside.

The contract

Why it matters

Inputs: name, environment, lambda_*, and tunables

Any root config calls it once to get the whole async stack

Outputs: queue_url, queue_arn, dlq_url, dlq_arn

Same module serves dev, staging, prod — values differ, code doesn't

Every variable has a description — the module's public docs

Swap the provider behind the boundary; callers don't change

aws_sqs_queue — Main Queue + Dead Letter Queue

SQS decouples the HTTP request from the work. The main queue holds jobs until a consumer picks them up; a
redrive_policy sends repeatedly-failing messages to a separate dead-letter queue instead of looping forever.

Main queue

Dead letter queue

visibility_timeout hides a message while it is being processed

Catches poison messages so they stop exhausting concurrency

redrive_policy = jsonencode({...}) references the DLQ ARN directly

message_retention_seconds keeps failures available for debugging

max_receive_count delivery attempts before giving up

Referenced by ARN — never a hardcoded string

aws_lambda_event_source_mapping — The Connector
The Event Source Mapping is the glue between SQS and Lambda. AWS polls the queue on your behalf and invokes the
function with a batch of messages. Neither the queue nor the function knows about the other — the ESM is the only
thing that links them.

How it works

Design rule

event_source_arn points at the main queue

Kept as a separate resource, not inline on the function

function_name points at the consumer Lambda

Tune batch_size or swap the source queue without touching Lambda

batch_size controls messages read per invocation

Both ARN references are variables — no hardcoded strings

aws_scheduler_schedule — EventBridge Scheduler

EventBridge Scheduler invokes a target on a recurring rate or cron expression. Here it triggers the same Lambda with a
scheduler payload so the function can run a periodic cleanup pass instead of processing a job.

Configuration

Identity

schedule_expression + scheduler_timezone as variables

A dedicated IAM role — not the Lambda execution role

flexible_time_window = OFF means exact timing

lambda:InvokeFunction scoped to the exact function ARN

input payload tags the invocation as source = scheduler

Each service gets its own scoped identity, never a wildcard

Demo 1 — Takeaway
Key Insight

One Lambda, three triggers — HTTP, queue, schedule.

A job flows POST /jobs → HTTP handler returns 202 and enqueues → SQS holds it → the ESM polls and
invokes the SQS handler, which writes results/{job_id}.json to S3. After max_receive_count failures the
message lands in the DLQ. Separately, the scheduler invokes the same function with {"source": "scheduler"}
to run cleanup. The dispatcher routes each event by shape — the module boundary hides which cloud
you're on.

KEDA — Kubernetes Event-Driven Autoscaler

KEDA scales Kubernetes Deployments from external event sources — SQS queue depth, Pub/Sub lag, Kafka, and many
more — not just CPU and memory. It installs as a cluster add-on and reads metrics no built-in autoscaler can see.

What it does

Why EKS teams care

Scales on external event metrics, not just CPU/memory

Scales up the moment the queue has work

Sources: SQS depth, Pub/Sub lag, Kafka, Prometheus, …

Scales back toward zero when drained — no idle cost

A poll-based consumer can sit at zero replicas when idle

Installed as a Terraform module via helm_release

Branch Protection Ruleset on main

Demo 2 — Takeaway
Key Insight

Apply the plan the reviewer saw — not a re-plan.

terraform plan -out=tfplan freezes the change set into a binary; upload-artifact carries it to the apply job;
apply tfplan applies exactly that — and aborts if state drifted since. Re-planning in the apply job, or
dropping -out, breaks the guarantee. The branch ruleset completes the picture: no change reaches main
without passing all three checks, and no apply runs against a plan the reviewer didn't see.
